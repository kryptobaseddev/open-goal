## 2. Approved harness signal

- CLEO's dispatcher sets **`CLEO_HOOK_PROVIDER`** when it spawns the tick
  (CLEO **T13884**), with values `claude-code` or `codex`; otherwise no signal.
- Map `claude-code` → harness `claude`, `codex` → `codex`, absent/other →
  `unknown`. **No `OCGOAL_HARNESS` variable and no `--harness` flag** — one
  convention only.
- On the dispatcher path, **version and capabilities stay null** (CLEO does not
  know them). The OpenCode adapter supplies name, serving version and
  capabilities directly.
- Claude integration: `cleo goal install --harness claude` writes **only**
  `<project>/.claude/settings.local.json` (Stop hook
  `cleo hook stop --provider claude-code`, PreToolUse heavy-command hook). No
  user-global `~/.claude`, `~/.codex` or `~/.config` writes.

## 5. The path off `.opencode/goals`

- **Canonical:** `.cleo/goals/<slug>/` (CLEO owns the protocol; config override
  allowed; invalid root fails closed).
- **Legacy:** `.opencode/goals/` stays **readable and resumable**; never deleted
  or silently rewritten.
- **Migration:** opt-in, dry-run first, byte-preserving; the owner chooses.
- **Archive:** `.cleo/goals-archive/` for the canonical root; legacy archive
  stays readable.
- **Guard:** the agent write guard covers the active root and the legacy path
  during the transition.
- The three contracts in this plan are written under the **current**
  `.opencode/goals`; Goal 3 moves future runs (and can migrate these if the owner
  opts in).
