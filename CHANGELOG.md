# Changelog

## 0.3.15 — 2026-10-14

- **Actual owner chat can start a reviewed draft (T105, P0)** — an explicit start/continue-goal instruction is fetched from the authoring session, bound to the latest actually displayed unchanged contract and mode, and consumed once in a distinct admission receipt. Expired form answers stay expired; quoted, conditional, foreign, changed, ambiguous, child-session and spent authority cannot launch. A sole matching pending launch question can be unheld without accepting it. Existing live goals still use guarded management, not inferred chat replacement.
- **Resolve the prerequisite, not another impossible resume (T105, P0)** — an unresolved amendment is reported before a resume/verify confirmation is offered. An owned unpresented prerequisite can restore its exact diff without accepting or resuming. A live session can stage a fresh validated review for a paused target; only actual new owner acceptance and an applied journalled generation retire conflicting unanswered proposals. Old consent and authorship are never transferred.
- **Release only an obsolete owned question (T105)** — server plugins may lack Core's `form.cancel` capability. Successful amendment disposition uses neutral interruption only for a sole nonce-bound obsolete form; unrelated holds stay protected. Restart recovery retires journal-proven obsolete proposals, never guesses acceptance from mailbox liveness.
- **Banner truth follows a real run** — no expired receipt is relabeled as running. The supported owner instruction creates a real admission/run, then the existing reactive banner follows that identity. Hot plugin reload is sufficient to load this patch; restarting alone never authorizes a launch.

## 0.3.14 — 2026-10-13

- **Missing identity is not changed identity (T104)** — incomplete live-goal targets name the missing `runId` or `sessionID` and request the complete fresh-inventory tuple. Full identity comparisons and actual-owner confirmation remain mandatory; no implicit target normalization or fallback goal is introduced.
- **Already resolved is not new authority (T104)** — an owned settled amendment reports its recorded status/result with `alreadyResolved:true`, `actionExecuted:false`, and `ok:false`. It never consumes another owner message or repeats acceptance/continuation. Executing, expired, unknown, and foreign reviews remain separately refused.
- **Report the receipt before changed status (T104)** — a settled lifecycle decision names its actual disposition rather than blaming the target's expected post-operation transition. Pending target/generation guards remain intact; failed or uncertain outcomes never become success.
- **Keep parallel-launch evidence honest (T103)** — passive isolated boundary traces correlate each slug and call result, including three already-live parallel requests and sequential controls. The historical OpenCode 2.0.27/provider report is not reproduced on immutable v0.3.12 with OpenCode 2.0.28 and is not claimed fixed. Launch expiry and cross-session recovery policy are unchanged.

## 0.3.13 — 2026-10-13

- **A failed attempt is not a failed run (T098)** — Composer and manager launch text correlates actual session/slug/lock/run presence and leads with the existing non-terminal goal's status. A late failed duplicate review stays a failed audit receipt; it does not replace the live run, invent successful admission or tell the owner to abort a working goal. Changed-lock and unrelated failures retain their own recovery details.
- **Safe duplicate-start guidance (T098)** — an occupied session refuses new admission while preserving its run. Same-goal requests explicitly say continue/manage the existing run, not “Abort it first”; different-goal requests point to a fresh-session launch instead of discarding current work. Snapshots expose optional actual session/lock identity for correlation, without treating launch progress or reported plan steps as criterion proof.

## 0.3.12 — 2026-10-13

The operation stays once-only and bound to the accepted next generation, never an approval of criteria.

## 0.3.2 — 2026-10-06

The trust-the-card release: the sidebar card always converges to disk truth, every card row is readable end-to-end, decisions ALSO ask through OpenCode's native in-composer ask tool, and the panel walkthrough is gated on a real pty. Every item is an owner-reported live defect from the v0.3.1 completion — fixed and proven under the goal loop itself (dogfood-5).

- **Fixed: the sidebar card froze at a stale snapshot across restarts (T072)** — two root causes. The complete transition reached `run.json` only if the summary builder's try-block survived its last line, so a reporting failure stranded the run as a zombie "running" on disk and the next server reload recovered it into "paused" while the run had actually finished (the lived paused/20-of-22/turn-7 card). The terminal write now persists at the transition itself, BEFORE the reporting layer, and pushes the final `updated` event; and `recover()` mirrors EVERY goal on disk — terminal ones included — so a re-attaching TUI's snapshot reads the disk truth (complete/N), never nothing. Proven by `test/host/refresh-convergence.test.ts`: reload mid-run → resume → complete → snapshot shows every criterion proven → a second reload keeps it complete.
- **Fixed: card rows truncate with no way to expand (T073)** — the compact card keeps its 12-line cap but always ends with an explicit expand affordance naming where the full rows live (`↳ F9 → Progress`); truncated rows carry a tab click-through target; the panel (the expanded view) renders every row FULLY at any width — statements wrap instead of ellipsizing, and the legend wraps to two short lines. `cardExpandedLines` renders the whole card uncut (all criteria with details, full plan, verdict); snapshot-tested compact and expanded.
- **Native ask-tool decisions (T075, owner directive)** — every decision point (needs_review, blocked, budget_limited, paused-after-verdict, complete, start-picker, amend-proposed, supersede-ack) ALSO asks through OpenCode's native in-composer form: the engine dispatches a decision prompt and the session's model asks the owner with the question tool (the only form-creation surface a server plugin has on 2.0.22), offering exactly the act-able choices (guidance rows marked as guidance). A form reply dispatches the SAME rpc act the TUI dialog carries; `decision.resolved` (via form/dialog) closes the other surface's dialog and a late stale reply is a no-op — answering either surface suppresses the other. The question-tool deferral keeps its engine-initiated exception during the ask window.
- **Fixed: "Decompose with CLEO" was a dead-end guidance row (T070)** — the complete decision's Decompose choice is a real act: it dispatches the CLEO decomposition prompt into the session (read the goal folder's summary/ledger, file each follow-up as a `cleo add --type task` with acceptance, link related tasks), and the dispatch lands in the ledger. - **Completion states the loop stopped (T071)** — at complete/failed/aborted the card shows `■ loop stopped — follow-ups: .opencode/goals/<slug>/`, the composer banner says the loop has stopped and where follow-ups live, and the post-goal summary opens with the same statement (the digest keeps it on screen). Silence after complete no longer reads as broken.
- **Deferred /goal commands acknowledge themselves (T069)** — a `/goal` command typed while a turn or form holds the session acknowledges IMMEDIATELY (a notice naming what is queued and why) and executes the moment it ends — never silent. Control and decision-answer commands (status/list/help/pause/abort/approve/reject) stay immediate; deferring an approval behind the decision-form's own ask turn would be circular.

- **Fixed: the command palette listed zero Goal commands on the real TUI (T064)** — the keymap layer registered from the app slot defaulted to `mode:"base"`, and base-mode layers are unreachable while any modal is open (the command palette itself registers `mode:"modal`). Approvals now match on the label prefix, persist to `.opencode/goals/.launch-approvals.json` (restart-durable inside the 10-minute window), and refusals name what was observed (no approval seen vs label mismatch vs expired).
- **Start clean (T059)** — `/goal start <slug> fresh` (and `goal_start({fresh:true})`) opens a NEW session owned by the goal, pins the run to it and prompts the kickoff there; the invoking session stays untouched (no clear-in-place API exists — none is pretended). - **T024 (the v0.3 epic) closed** — all 18 child acceptance criteria bound to their children's verified evidence chains; both finished dogfood runs (dogfood-buildout, ship-v03-feedback-loop) archived with history intact.

## 0.3.0 — 2026-10-05

The feedback-loop release: every decision persistent, actionable, visible. Built and proven under the goal loop itself (dogfood-3).

- **Fixed: the verifier child's silent empty exchange (T044)** — the root cause of all four dead verifier rounds on the main host. The child request now carries an explicitly resolved model (the parent session's live model, then the location default; recorded as a `verifier-model` ledger event), and an entirely empty exchange is retried once with an explicit last-chance prompt and always recorded (`verifier-empty` rounds, `empty after N round(s)` verdict detail) — never silent.
- **Post-goal summary (T045)** — on complete / needs_review / budget_limited the engine builds a summary from data the run already has: per-criterion outcomes with provenance (owner-approved and fallback-passed carry explicit caveats), the scope audit, restated non-goals, mid-run findings from the ledger, and follow-up prompts including the CLEO-install suggestion when the project has no `.cleo` workspace. Rendered as a `summary` rpc event + TUI dialog, a `goal.summary` transcript row, and a persisted evidence document.
- **Flagged completion scope audit (T046, owner decision)** — plan steps with `proves: []` and no recorded work, and `scope.in` lines mapping to no criterion, surface in the summary as *discussed but unproven*. Completion is never blocked by them (deliberately loose plans must not deadlock).
- **Owner-final beats host re-checks too (T057)** — the T051 fix covered the verifier only; the live C15 stomp came from a HOST re-check failing a stale needle after the owner approved it. Criteria passed `by: human` are now skipped by host re-verification as well and recorded as *approved by the owner (final)*.
- **Goals escape their session (T049)** — owner actions fall back to the project's unique non-terminal goal from any session (`/goal approve C4 [slug]`), and `/goal attach <slug>` moves a stopped goal into the current session (live goals wait for their turn to end). The RPC list carries attachable flags; the palette gains "Goal: attach/switch to a goal".
- **Decision dialogs at every decision point (T050)** — needs_review, paused-after-verdict, blocked, budget_limited, amend-proposed, supersede-ack and complete each emit a decision payload (kind, cause, structured choices); the TUI renders it as a selectable dialog wired to `rpc.act`. Nobody types an approval by hand.
- **Actionable message content (T054)** — one message registry: every engine notice carries the cause plus concrete choices, rendered inline for toasts and attached as structured choices for dialogs. A unit suite pins that no notice is actionless.
- **Persistent terminal feedback (T052)** — verdicts, owner actions, amendments, blocks, budget stops and completions land as transcript notice rows the agent sees next turn (queued rows deliver on the session's next turn), and an action-required state rides the sidebar view until the status resolves.
- **Live activity tracer (T053)** — the engine records what it is doing (turn, verifying, verifier child with its model, waits with countdowns, cooldowns); a pure formatter renders it with elapsed time above the composer and in the panel. Snapshot-tested; zero model cost.
- **Dashboard rework (T056)** — the sidebar card is capped at 12 lines (status, one bar, current step, next action, one action-required line — never a timeline); the panel is organized into Now / Progress / Decisions / Goals tabs with plain-language criteria and a C/I/S legend footer; decision rows are native Select components dispatching `rpc.act`; the panel opens on demand (`leader+g`, `tab` cycles) instead of displacing the sidebar; the raw ledger timeline is gone from the UI (it stays in the file).
- **Fixed: the dashboard freeze (T058)** — a dropped or late-attaching event stream could freeze the card at its first snapshot for a whole run (seen live). The TUI now re-fetches stale snapshots on renders and on a 4-second ticker for live goals; events remain the fast path.
- **Authoring rules against contract drift (T055)** — the write-goal skill forbids exact version-string needles and teaches prefix/semantic version checks, with a worked release-goal example (`startsWith`, changelog anchored on major.minor).
