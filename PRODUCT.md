# Product

## Register

product

## Users

OpenCode V2 terminal users reviewing autonomous goal runs across project sessions, using pointer and keyboard input at varying terminal widths and heights.

## Product Purpose

Make the existing Goals manager readable and operable: inspect status and evidence, expand details before deliberately jumping, operate only the selected run, and return visibly to the basic sidebar. Plan progress is not host-proven completion.

## Brand Personality

Native, direct, restrained. Preserve OpenCode's existing terminal theme and typography; no new brand, provider, web app or decorative redesign.

## Anti-references

The owner's supplied cut-off manager screenshot, an unstructured wall of contract prose, invisible exit/focus controls, highlighted but non-operable options, and competing approval popups.

## Design Principles

- Preserve existing Goals tab, project-wide cards and expand-before-jump.
- Pin status, session, proof/plan facts and actions; make detailed prose word-wrapped and explicitly scrollable.
- Keep “F9: sidebar” and a selectable Close control visible.
- Use native Composer forms as the only lifecycle decision surface.
- Confirm real control activation and selected-target isolation, not screenshot text alone.

## Accessibility & Inclusion

The owner approved keyboard and pointer operation and narrow/wide terminal verification. Focus and selected state must be explicit; semantic state must not rely only on color. Use the host's native theme and terminal-cell measurements. Web WCAG/browser audit tiers do not measure this OpenTUI surface and are not claimed as passing.

## Approval

Owner selected “Repair current manager” in the native Manager repair question, approving the fixed header, compact facts, word-wrapped scrollable details, visible actions/focus and Close/F9 return controls. The original goal remains paused; this product decision does not resume it or waive any contract check.
